# drmSEM capability surface

**Current development version:** 0.5.0 (`DESCRIPTION`); `NEWS.md` carries additional unreleased "maturity hardening" work under a `(development version)` heading not yet version-bumped.
**Lifecycle:** experimental (README badge; `docs/design/05-roadmap.md` still lists 0.4's engine-dependent items as open).
**Scope:** this file is a capability inventory of what `drmSEM` exports and what evidence backs it — it is not a release certificate, not a claim that every path, effect, or model comparison is scientifically correct for a given dataset, and not a substitute for `NEWS.md`, `docs/memory/OPEN_QUESTIONS.md`, or `docs/memory/VALIDATION_LEDGER.md`. When this file and those disagree, re-derive from `NAMESPACE`, `R/`, and `tests/testthat/` — those are the ledger; this file is a projection of it. Evidence below includes a fresh full local test run (2026-07-19, `drmTMB` 0.6.0.9000 actually installed and fitting) — the strongest evidence this file cites, since several repo docs (e.g. `docs/design/04-validation-plan.md`) predate that and describe the drmTMB-integration tests as unrunnable in a dev container.

## What the package is for

`drmSEM` is a **distributional piecewise structural equation modelling (SEM) layer built on the `drmTMB` fitting engine**. `drmSEM` never fits its own likelihoods: every endogenous node is exactly one `drmTMB` fit, and the SEM is piecewise (a graph of separately fitted local models, in the tradition of `piecewiseSEM`). Its distinguishing feature is that a causal path does not have to target the mean (`mu`) — it can target any modelled distributional component of a node: residual scale (`sigma`), shape (`nu`), zero-inflation (`zi`), hurdle probability (`hu`), random-effect scale (`sd(group)`), or bivariate residual correlation (`rho12`). On top of that graph, `drmSEM` provides component-labelled path tables, an any-component d-separation test with Fisher's C, and Monte-Carlo (never coefficient-product) direct/indirect/total effects that separate a mean-mediated channel from a distribution-mediated (Jensen-gap) channel.

See `docs/design/13-missing-data.md`. |

## Important limits

- `drmSEM` never fits its own likelihoods. Every quantity it reports — a path coefficient, a d-separation p-value, an effect, a correlation — traces back to one or more `drmTMB` fits; `drmSEM` supplies the graph, the decomposition, and the honesty checks around them.
- Effects are **conditional** (random effects at zero), not marginal/population-averaged; a causal path into a random-effect scale has no effect-decomposition entry today (OQ-9).
- A declared bivariate correlation (`rho12`/`corpair`) is a **grammar object**, never a fitted number — `estimate` is hardcoded `NA_real_` everywhere in the package. Do not read a `drm_pair()`/`covary()` declaration as evidence of an estimated correlation.
- A feedback (cyclic) SEM gets an **equilibrium mean-only** `total_effects()`; it never gets an indirect/path decomposition, and node-wise fitting of a declared cycle is acknowledged as statistically inconsistent under simultaneity (a warning, not a fix).
- Calibration evidence (Type-I/power for d-sep, interval coverage for effects, model-selection recovery rate) is validated only for the specific DGP grids that were actually run (`docs/memory/OPEN_QUESTIONS.md` OQ-6, `docs/design/12-coverage-calibration.md` C-1/C-3); it does not generalize to arbitrary graphs, families, or sample sizes.
- `check_sem()` is covered only for its `nobs` column (`test-missing-data.R`, 2026-08-14); `converged`, `vcov_available`, `sampler`, the `print` method and every warning branch remain untested — treat those as unverified until a test exists.
- The package is not CRAN-submittable while `drmTMB` and `symbolizer` remain GitHub `Remotes:` in `DESCRIPTION` (`NEWS.md`, "development version" section) — this is an explicit, acknowledged external release blocker, not an oversight.
- The R-only twin: there is no Julia twin or cross-language parity claim (unlike `hsquared`/`HSquared.jl`).
