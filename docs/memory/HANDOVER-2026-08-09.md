## 3. The plan — `because`-gap programme

Full plan: **`~/.claude/plans/warm-launching-crane.md`**. Engine asks also live in
`docs/memory/DRMTMB_ISSUES.md` (new dated section, 9 items).

Origin: the `because` package (von Hardenberg et al., RSTB-2025-0491, **under review — the
PDF is confidential, in `intake/`, and must not be quoted or distilled anywhere public**)
appeared to dominate drmSEM on five axes. The audit found the comparison misleading both
ways:

- **Ordinal already works end-to-end** — proven live: fits, `paths()` labels it, `dsep()`
  runs Fisher's C, `indirect_effects()` decomposes it (recovery 0.518/0.875 vs true 0.5/0.9).
  drmSEM ships this today and does not know it. `categorical()` does **not** — it is not a
  fitted response family in drmTMB.
- **`relmat(K=)` is strictly more flexible for spatial work than drmTMB's own `spatial()`**,
  whose only kernel is a fixed exponential with a heuristic range.
- **`because` cannot target non-mean components at all.** Its node model is
  `g(μ) = α + ΣβV + Zu` — the mean only. Parity is the wrong goal; drmSEM's differentiator
  is untouched.

Suggested order (see the plan for detail): triage → **S5** (the bug in §5) → **S6 prototype**
(graph-derived imputation) → **S1/S1b** → **S2** (m-separation, the flagship) → S3 → S4.

## 4. Do-not-repeat

- **Never sign a figure off from its plot code.** The Confidence Eye contract says so, and
  today proved it twice. `paste0()` **drops names**, so deriving pale fills from outline
  colours handed `scale_fill_manual()` an unnamed vector, which assigned them positionally
  in alphabetical order and paired the mean-mediated outline with the distribution-mediated
  fill. Every test passed. Only the rendered PNG showed it. Guarded now by a test comparing
  each polygon's built fill to its own outline.
- **Never build a Confidence Eye taper from `dnorm()`.** The contract states the taper is a
  visual cue, not a density. Use `drmSEM:::drm_confidence_eyes()`.
- **A recorded warning is not an applied warning.** Darwin's review flagged that
  "bet-hedging" is a precise term, that drmSEM is cross-sectional and cannot represent the
  fluctuating-environment literature where bet-hedging pays, and that the caption must not
  gesture at it. I wrote that warning into the script header and then used the label anyway
  — on the live site. In bet-hedging theory variance is *adaptive*; in this example the
  environment is constant and variance is purely a cost, so the label predicted the opposite
  of the figure. Renamed to the cost of variance under diminishing returns;
  conservative/mixed/diversified → consistent/intermediate/variable.
- **Review coverage is a thing to design, not assume.** Darwin (who knew) reviewed a *plan*
  and never saw the page. Florence and Tufte reviewed the *page* but were briefed on
  presentation, not on whether the biology was named correctly. The README prose was written
  after every review closed and pushed unread. If an artifact's text is written late, it has
  had no review.

## 5. Live bug found, not yet fixed (this is S5, and it is real)

drmSEM has **no missing-data policy at all** — no `na.omit`, `complete.cases` or `na.action`
anywhere in `R/`. `drm_sem()` hands one `data` frame to every node (`R/drm_sem.R:250`) and
each drmTMB fit then drops incomplete rows by its own rules. Reproduced live, NAs in two
different columns of a 300-row frame:

```
drm_sem() SUCCEEDED silently.  nobs: node m = 270, node y = 240
indirect_effects() -> "number of items to replace is not a multiple of replacement length"
```

Two defects: nodes silently fitted on **different samples** (a correctness problem — paths
come from different row sets and the basis set is tested against a third), and an
undiagnosed raw subscript crash instead of a reported cause. Fix before any drmTMB
missing-data feature is consumed, since those features change *which* rows each node uses.
